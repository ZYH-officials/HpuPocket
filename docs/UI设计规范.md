# HpuPocket UI 设计规范

适用于 HpuPocket Android App 与课程桌面小组件。App 使用 Jetpack Compose、Material 3 Expressive 和 Android 12+ 动态取色；小组件使用 RemoteViews，视觉语言与 App 保持一致。

## 1. 设计原则

1. **内容优先**：课程、时间、地点、剩余电量等关键信息先被看见，装饰不争夺注意力。
2. **少而清楚**：文案直接说明状态和操作，不写问候式废话，不重复展示同一含义。
3. **使用成熟组件**：优先 Material 3 官方组件和项目已有的 `pressable`、`LoadingIndicator`，不重复造轮子。
4. **同层级同样式**：同级标题、卡片、按钮、空状态和弹窗保持统一，页面不各造一套规则。
5. **真实设备验收**：UI 完成后必须在真机截图，检查浅色、深色、长文本、小屏和滚动场景。

## 2. 色彩

### 2.1 主题色

- 默认使用系统动态取色，不在业务页面硬编码品牌紫色。
- 页面颜色优先取 `MaterialTheme.colorScheme`：
  - 页面背景：`background`。
  - 普通卡片：`surfaceContainerLow`。
  - 强调卡片：`primaryContainer` 或 `secondaryContainer`，需要弱化时可使用约 45%–50% 透明度。
  - 主文字：`onSurface`。
  - 辅助文字：`onSurfaceVariant`。
  - 错误、透支和失败：`error` / `onErrorContainer`。
- 分割线使用 `outlineVariant`，宽度通常 `0.5dp`，不使用高对比实色边框。

### 2.2 业务色

- 课程色板仅用于区分课程、色条和课程块，不承担成功或错误语义。
- 剩余电量为负数时使用 `error`，不能只靠负号传达异常。
- 空闲教室的绿色只表示“空闲”，其他状态必须同时有文字，不只靠颜色区分。
- 新页面不得新增随意色值；确需新增时先说明语义，并同时验证深浅色对比度。

## 3. 字体与数字

优先使用 Material typography；旧页面迁移时按以下字阶对齐，不再新增无规律的散点字号。

| 用途 | 推荐样式 | 旧页面迁移参考 |
| --- | --- | --- |
| 首页主问候 | `headlineMedium` + Bold | 28sp 左右 |
| 主标签页标题 | `headlineMedium` + Bold | 28sp 左右 |
| 功能子页标题 | `titleLarge` + SemiBold | 22sp |
| 弹窗标题 | `titleLarge` + SemiBold | 20sp |
| 卡片主标题 | `titleMedium` + SemiBold | 16sp |
| 分区标题 | `titleMedium` + Medium | 15–16sp |
| 正文、课程名 | `bodyMedium` / `bodyLarge` | 13–15sp |
| 辅助信息 | `bodySmall` | 11–12sp |
| 标签、状态 | `labelSmall` / `labelMedium` | 10–12sp |
| 关键余额、合计 | 24–28sp + Bold | 单位使用 11–12sp |

规则：

- 正文不使用 Light；Medium 用于标题和关键字段，Bold 只用于页面主标题和关键数字。
- 普通界面文字不得小于 `10sp`。空间不足时减少次要信息、换行或省略，不能继续缩字。
- 时间、电量、合计等数字应保持稳定对齐；同一组数字使用相同字号和字重。
- 长课程名主标题可一行省略；需要完整理解时允许两行。地点、教师等副标题保持一行省略。
- 所有 `maxLines` 限制都应同时设置 `TextOverflow.Ellipsis`，避免生硬裁字。

## 4. 间距与布局

采用 4dp 基础网格，常用间距为 `4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 32dp`。

- 主内容左右边距：`20dp`。
- 卡片内边距：普通卡片水平 `16dp`、垂直 `12–16dp`；强调卡片可用 `18dp`。
- 卡片之间：`10–12dp`。
- 分区标题与内容：`8–12dp`。
- 同组字段：`4–8dp`。
- 页面底部预留至少 `24–30dp`，避免内容贴住系统导航区。
- 不连续叠加多个无意义 `Spacer`；一个位置只保留一个明确的布局间距。
- 可点击区域至少 `48dp × 48dp`，图标本身通常为 `24dp`。
- 小屏、横屏、键盘或大字体可能溢出时，页面和弹窗内容必须可滚动。

## 5. 圆角与容器

| 容器 | 圆角 |
| --- | --- |
| 课程块、小型标签 | 10dp |
| 记录行、输入辅助容器 | 12dp |
| 普通数据卡、列表卡 | 16dp |
| 页面主视觉、关于页分组卡、重点汇总卡 | 20dp |
| 按钮、菜单、导航指示器 | 使用 Material 组件默认值 |

- 普通内容卡优先使用低层容器色，不额外添加阴影。
- 一个信息组只使用一层卡片，避免“卡片套卡片”；弹窗中的汇总卡与日期行可作为信息层级例外。
- 分割线只用于分隔同组内容，不作为所有卡片的固定装饰。

## 6. 导航与页面骨架

### 6.1 底部主导航

- 仅保留“首页 / 课表 / 我的”三项。
- 使用标准 Material 图标：`Home`、`DateRange`、`Person`。
- 图标和标签各司其职，不用“首、课、我”等文字冒充图标，不重复标签。
- 标签使用 `NavigationBarItem` 默认 typography，不单独缩小字号。

### 6.2 主标签页

- 首页可展示大标题、日期和重点提醒。
- 课表页以周切换和课程内容为优先，不让底部概览挤压课程区域。
- 我的页以账号信息和设置入口为主，小屏下整页必须能滚动到底。

### 6.3 功能子页

统一顺序：状态栏留白 → 返回行 → 页面标题 → 可选副标题 → 可滚动内容。

- 返回行水平边距 `8dp`，使用 `TextButton` 和“‹ 返回”。
- 标题水平边距 `20dp`，采用 `titleLarge + SemiBold`。
- 刷新等页面级操作放在标题行尾部；内容级操作放在对应卡片中。
- Android 返回键与页面返回按钮行为一致。

## 7. 常用组件

### 7.1 按钮

- 一个区域只设置一个主按钮；次级操作使用 `TextButton` 或官方轮廓按钮。
- 不用裸 `Text + clickable` 模拟“重试”“刷新”等按钮。
- 图标按钮必须有 `contentDescription`；纯装饰图标设为 `null`。
- 刷新中保留按钮位置并显示加载状态，避免布局跳动。

### 7.2 列表与卡片

- 主信息在前，状态和时间在尾部；操作区不能被长文本挤压。
- 列表项之间优先留白或细分隔线，不给每一行都套厚重边框。
- 同类列表的空状态、加载状态和错误状态应占用相近位置，减少页面跳动。

### 7.3 弹窗

- 标题直接说明任务，例如“用电记录”“选择学期”。
- 选择类弹窗保持一种样式；不为不同页面定制互相冲突的容器和标题。
- 内容可能超过屏幕时使用 `heightIn` 加纵向滚动，按钮始终可见。
- 主要确认操作放右侧，关闭或取消语义清楚；破坏性操作必须二次确认。

### 7.4 表单

- 输入框标签使用名词，错误提示写在对应字段附近。
- 登录按钮在必要数据未就绪时禁用或给出明确提示，不能点击后无反应。
- 键盘弹出时输入框和提交按钮仍能到达。

## 8. 状态反馈

- 页面居中加载：`LoadingIndicator` 32–40dp，可配一行简短说明。
- 卡片内联加载：16–20dp，避免过小看不清。
- 不使用静态“加载中”掩盖接口失败；加载、空结果和失败必须是三个独立状态。
- 空状态说明“没有什么”，必要时给出下一步，例如绑定宿舍后刷新。
- 错误状态使用 `error` 色并提供“重试”，错误详情保持简短。
- Toast 用于轻量结果；需要用户决策或阅读的内容使用弹窗。

## 9. 动效

- 页面、按钮和指示器优先使用 `MaterialTheme.motionScheme` 与官方组件默认动效。
- 点击反馈使用项目已有 `Modifier.pressable`，不要再实现第二套缩放逻辑。
- 动效用于解释层级和状态变化，不为卡片添加无意义的循环动画。
- 加载与刷新不能通过布局跳动制造“动感”。

## 10. 页面专项规则

### 首页

- 顺序保持：问候与日期 → 重点提醒 → 今天课程 → 快捷入口 → 一言。
- 快捷入口不恢复副标题。
- 长课程名和一言出处必须省略，不挤压状态、时间或刷新按钮。

### 课表

- 课程色、时间、教室是核心；小字号不能成为压缩更多内容的手段。
- 周切换在首尾周禁用无效操作，触控区至少 48dp。
- 今日课程状态条在空间不足时换行，不横向溢出。

### 设置与关于

- 设置使用分组小标题和导航行；危险操作与普通设置分开。
- 关于页保持居中 Hero、分组卡片和真实 App 图标，不添加占位图。

### 宿舍电量

- 余额优先于用电记录；负余额标红。
- 记录按天聚合，同一天的多表数据合并，全零日期不占用列表。
- 完整记录弹窗先显示房间和近 14 天合计，再显示可滚动的每日记录。

### 桌面小组件

- 支持 2×2 起缩放，课程列表可滚动，不按 MIUI 上报高度猜行数。
- 保持 20dp 根圆角、清楚的时间与课程层级，深浅色资源同步维护。

## 11. 可访问性与验收

每次 UI 修改至少检查：

- [ ] 构建使用新源码，APK 时间戳正确，覆盖安装不更换签名。
- [ ] 真机截图并放大检查文字、间距、圆角和对比度。
- [ ] 长课程名、长地点、负数、空列表、接口失败和加载中均有合理表现。
- [ ] 页面可滚动到底，弹窗按钮不被键盘或内容挤出屏幕。
- [ ] 浅色与深色均无白字看不清、状态仅靠颜色区分等问题。
- [ ] 首页、课表、我的之间切换无回归；返回键行为一致。
- [ ] 不通过 adb 代替用户点击或滑动；由用户打开目标页面后再截屏。

## 12. 旧页面迁移优先级

**优先修正：**

1. 底部导航文字图标、启动页旧加载指示器等明显不一致。
2. 长文本裁切、操作区被挤压、重复间距和错误文案。
3. 小屏不可滚动、无效周切换、失败状态显示成加载中等可用性问题。

**逐页截图后再改：**

1. 全局 typography 一次性替换。
2. 空闲教室矩阵与课表时间轴的小字号布局。
3. 所有选择弹窗、普通卡片圆角和页面切场动效的统一。

旧页面不要求一次重写；每次修改只迁移触及的区域，新页面直接遵循本规范。
